model_notes: "Fragment set used by cambrian_agent_sdk/react.py run_think. These are volatile by definition and always go into messages, never into the system blocks, so the system text stays byte-identical across the turns of a run (the provider cache depends on it). tool is the repr of the tool name. v2 adds inferred-answer-native: under native tool-calling plain text is not an answer, the final_answer tool is. v3 adds the per-agent skill access notes (decisions/skill-access-grants.md): skill-pending and skill-denied answer a use_skill on a skill outside the agent's set that an operator did not grant in this run, and skills-requestable lists find_skills hits outside the set; every v2 section is byte-identical. v4 adds the ADR-0145 D3 evidence re-prompts (execution.workers.evidence_reprompt): when a plain-text reply arrives and the run has gathered no evidence (no tool ran, no memory or tool result, no upstream or seeded evidence), the re-prompt offers delegation (inferred-answer-no-evidence-delegate, delegate is the delegation tool name) or the next tool (inferred-answer-no-evidence-tool) instead of pushing toward final_answer; the decision is structural, made in code, never by matching the reply text; every v3 section is byte-identical. v5 adds the ADR-0150 D4 stopping-rule notes of the single-agent lane: lane-stuck and lane-stuck-failing are the one corrective message of the stuck detector (the same action with the same result, or the same action failing, repeats times), and lane-summary is the instruction of the one tool-less summary call at a runaway cap or after the corrective message did not help (reason says which); every v4 section is byte-identical. v6 adds invalid-args: a native tool call whose arguments are not valid JSON while the provider did NOT stop at the output limit was malformed, not cut off, so it gets this note (tool and the JSON error) instead of the truncation note (T-20261114-sdk-reports-malformed-native-tool-call); every v5 section is byte-identical."

Do not answer such a question from general knowledge, and do not promise to look it up: only the tool call does that. If the reply needs no such facts, emit final_answer with it.</note>

<!-- section: inferred-answer-no-evidence-tool -->

If the answer depends on facts you have not read, call the tool for your next step now. Do not answer from general knowledge, and do not describe what you will do: only the tool call does it. If the task needs no lookup, emit final_answer with the answer.</note>
