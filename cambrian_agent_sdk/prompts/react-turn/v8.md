<!-- section: answer-items -->

{{items}}
</items>
When you call final_answer, give answer as your answer text, and item_results with one entry per item: {"item": "<id>", "status": "satisfied" | "not_found" | "not_permitted" | "failed", "values": [{"name": "<short name>", "type": "<type>", "value": <value>, "evidence_ref": "<ledger id>"}], "reason": "<why, when not satisfied>"}. Types: string, number, money, date (an ISO date such as 2026-11-08), id, ref, citation, bool, list, object. A ref is a ledger id (led_...) and nothing else; an identifier a system gave a record (a message id such as MSG-000173, a case reference, an invoice number) is an id, and its evidence_ref is the ledger entry it appears in. For a document item (a letter, a draft, a text to write), the full text is your answer: put it in answer, and do not create, send, file or save it in any system unless an item of type write asks for that. Every value cites the ledger entry it was read from: the _ledger_ref or cid of one of your own tool results, or a reference in your inputs. A number, money amount or date must come from a tool result or a calculation, never from your own arithmetic, and must appear in the entry you cite. Say not_found only after you searched; say not_permitted only when a tool call was refused. Values are data: copy them exactly as the evidence states them.
